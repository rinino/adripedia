Git

Guida pratica a Git: che cos'è, come installarlo su Windows e Linux e i comandi che servono davvero, con esempi pronti da copiare. Contenuti verificati sulla versione 2.56.0.

Versione documentata: Git 2.56.0 e Git for Windows 2.56.0.windows.4 (ottobre 2026). Git è distribuito con licenza GPLv2.

Che cos'è Git

Git è un sistema di controllo di versione distribuito (DVCS): registra la storia di un progetto, permette di tornare indietro, lavorare su più rami e collaborare senza dipendere da un server centrale. È stato creato da Linus Torvalds nel 2005 per gestire il kernel Linux ed è oggi lo standard di fatto per il codice sorgente.

In un DVCS ogni copia del repository contiene tutta la storia: puoi fare commit, consultare il log e creare branch anche offline. Il server remoto serve per condividere e sincronizzare, non per lavorare.

Git non è GitHub

Git è lo strumento che installi sul computer. GitHub, GitLab, Bitbucket e Codeberg sono servizi di hosting che ospitano repository Git e aggiungono funzioni come pull request, issue e CI. Puoi usare Git benissimo senza alcun servizio esterno.

I concetti chiave

TermineSignificato
Repository Il progetto con tutta la sua storia. La cartella .git contiene i dati; i file che vedi sono il working tree.
Working tree I file su cui stai lavorando, nella cartella del progetto.
Staging area L'area di preparazione (index): ciò che hai scelto di includere nel prossimo commit con git add.
Commit Un'istantanea immutabile dello stato del progetto, con autore, data, messaggio e un identificatore SHA.
Branch Un puntatore mobile a un commit. Il branch predefinito oggi si chiama di solito main.
HEAD Indica il commit o il branch su cui sei posizionato in questo momento.
Remote Un repository remoto collegato, di solito chiamato origin.
Upstream Il branch remoto che il tuo branch locale segue (per esempio origin/main).
Tag Un'etichetta fissa su un commit, usata soprattutto per le versioni (v2.56.0).

I tre stati di un file

Git vede i file in tre passaggi:

  1. Modificato — il file è cambiato nel working tree ma non è ancora in staging.
  2. In staging — la modifica è stata aggiunta con git add e farà parte del prossimo commit.
  3. Registrato — la modifica è stata salvata nella storia con git commit.

Il flusso di lavoro tipico

git clone https://example.com/progetto.git
cd progetto

# modifica i file...

git status
git add file.txt
git commit -m "Descrizione della modifica"
git push

Da quel momento il ciclo è sempre lo stesso: modifichi, controlli con git status e git diff, prepari con git add, registri con git commit e condividi con git push.

Primi passi

Dopo l'installazione, configura la tua identità una volta sola:

git config --global user.name "Nome Cognome"
git config --global user.email "nome@example.com"
git config --global init.defaultBranch main

Poi scegli se creare un repository o clonarne uno esistente:

# nuovo repository nella cartella corrente
git init

# copia locale di un repository esistente
git clone https://example.com/progetto.git
Da dove continuare: i comandi di installazione sono nei tab Installazione Windows e Installazione Linux; il riferimento completo è nel tab Comandi.

Versioni e compatibilità

Questa guida è verificata sulla versione 2.56.0. I comandi di uso quotidiano sono stabili; git switch e git restore esistono dalla 2.23, quindi su distribuzioni molto vecchie puoi trovare solo git checkout.

Installazione su Windows

Il pacchetto di riferimento è Git for Windows: include Git, Git Bash, una GUI e Git Credential Manager. La versione documentata è 2.56.0(4).

Requisiti

  • Windows 10 o 11 (x64); esiste anche la build ARM64.
  • PowerShell o Prompt dei comandi per usare winget.
  • Permessi di amministratore per un'installazione valida per tutti gli utenti.

Metodo 1 — Installer ufficiale

  1. Apri git-scm.com/install/windows.
  2. Scarica Git for Windows/x64 Setup (oppure la versione ARM64).
  3. Avvia l'installer e segui la procedura guidata.

Scelte consigliate durante l'installazione:

  • Editor predefinito: quello che usi davvero (VS Code, Notepad++, Vim).
  • PATH: «Git from the command line and also from 3rd-party software», così git funziona da PowerShell e da altri strumenti.
  • HTTPS transport: OpenSSL o la libreria di Windows; entrambe funzionano.
  • Line endings: «Checkout Windows-style, commit Unix-style» (core.autocrlf=true).
  • Terminale: MinTTY (Git Bash) è la scelta predefinita e va bene.
  • Credential Manager: lascialo attivo, evita di digitare la password ogni volta.
# verifica
git --version
# git version 2.56.0.windows.4

Metodo 2 — winget

Da PowerShell:

winget install --id Git.Git -e --source winget

Per aggiornare:

winget upgrade --id Git.Git -e
Il pacchetto Git.Git di winget non è mantenuto dal progetto Git for Windows e può restare indietro rispetto all'ultima versione. Dopo un aggiornamento di sicurezza controlla sempre git --version.

Metodo 3 — Chocolatey

choco install git
choco upgrade git

Vale la stessa avvertenza di winget: il pacchetto è di terze parti.

Versione portable

Se non puoi installare nulla, scarica PortableGit (archivio autoestraente), estrailo in una cartella e usa git-bash.exe. Per avere git nel PATH, aggiungi la sottocartella cmd alle variabili d'ambiente.

Configurazione iniziale

git config --global user.name "Nome Cognome"
git config --global user.email "nome@example.com"
git config --global init.defaultBranch main
git config --global core.autocrlf true
git config --global core.editor "code --wait"
git config --global credential.helper manager
git config --global --list
ImpostazionePerché
user.name, user.emailFirmano ogni commit; l'email è quella che vedranno gli altri.
init.defaultBranchNome del branch iniziale: main è lo standard attuale.
core.autocrlfConverte i fine riga: CRLF in checkout, LF nel repository.
core.editorEditor usato per i messaggi di commit e il rebase interattivo.
credential.helpermanager usa Git Credential Manager, incluso in Git for Windows.

Per controllare da dove arriva un'impostazione: git config --global --show-origin --list.

Git Bash, PowerShell o WSL

  • Git Bash offre un terminale POSIX con i comandi Unix più comuni.
  • PowerShell funziona bene per Git; attenzione alle virgolette e ai percorsi con spazi.
  • WSL è un'installazione separata: Git dentro WSL ha la sua configurazione e i suoi file. Se usi entrambi, tieni aggiornati tutti e due.

Aggiornare e disinstallare

# aggiornamento da Git Bash
git update-git-for-windows

# alternativa con winget
winget upgrade --id Git.Git -e

# disinstallazione
winget uninstall --id Git.Git

Dopo l'aggiornamento chiudi e riapri i terminali aperti.

Problemi comuni

  • git non riconosciuto: il PATH non è aggiornato; riapri il terminale o reinstalla scegliendo l'opzione PATH corretta.
  • File che risultano tutti modificati: controlla core.autocrlf e la configurazione dell'editor.
  • Credenziali richieste ogni volta: verifica git config --global credential.helper.

Installazione su Linux

Su Linux Git si installa quasi sempre dal repository della distribuzione. La versione disponibile dipende dalla distro: se ti serve l'ultima, usa il PPA su Ubuntu o compila dai sorgenti.

Debian e Ubuntu

sudo apt update
sudo apt install git

Per l'ultima versione stabile su Ubuntu:

sudo add-apt-repository ppa:git-core/ppa
sudo apt update
sudo apt install git

Fedora

sudo dnf install git

Su Fedora 21 e precedenti il comando era yum install git.

Arch Linux

sudo pacman -S git

openSUSE

sudo zypper install git

Alpine Linux

sudo apk add git

Gentoo

sudo emerge --ask --verbose dev-vcs/git

Nix e NixOS

# profilo utente
nix profile install nixpkgs#git

# metodo classico
nix-env -i git

Su NixOS aggiungi pkgs.git a environment.systemPackages.

RHEL, CentOS, Rocky Linux e AlmaLinux

sudo dnf install git

Queste distribuzioni tendono a fornire versioni più vecchie. Se ti serve una versione recente, valuta un repository di terze parti oppure la compilazione dai sorgenti.

Compilare dai sorgenti

Serve per avere l'ultima versione su distribuzioni che non la forniscono. Le dipendenze cambiano da distro a distro; su Debian/Ubuntu: 

sudo apt install build-essential libssl-dev libcurl4-openssl-dev \
  libexpat1-dev gettext zlib1g-dev

wget https://www.kernel.org/pub/software/scm/git/git-2.56.0.tar.gz
tar -xzf git-2.56.0.tar.gz
cd git-2.56.0

make prefix=/usr/local all
sudo make prefix=/usr/local install
Se installi in /usr/local, assicurati che sia nel PATH prima di /usr/bin. Controlla con which git.

Verifica

git --version
which git

Configurazione iniziale

git config --global user.name "Nome Cognome"
git config --global user.email "nome@example.com"
git config --global init.defaultBranch main
git config --global core.autocrlf input
git config --global core.editor "code --wait"
git config --global pull.rebase false
git config --global --list

Su Linux core.autocrlf input converte i CRLF in LF nel repository senza modificarli nel working tree.

Per non digitare la password a ogni push, scegli un credential helper:

# salvataggio in chiaro in ~/.git-credentials (comodo, poco sicuro)
git config --global credential.helper store

# cache in memoria per un'ora
git config --global credential.helper "cache --timeout=3600"

# integrazione con il portachiavi di sistema (GNOME/KDE)
git config --global credential.helper libsecret

Per libsecret serve il pacchetto libsecret e, su alcune distro, git-credential-libsecret.

Chiavi SSH

Se usi GitHub, GitLab o un server Git via SSH, crea una chiave e aggiungila al servizio: 

ssh-keygen -t ed25519 -C "nome@example.com"
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub

Copia il contenuto di id_ed25519.pub nelle impostazioni SSH del servizio. Verifica con ssh -T git@github.com.

Aggiornare e disinstallare

# Debian/Ubuntu
sudo apt update && sudo apt upgrade git

# Fedora
sudo dnf upgrade git

# Arch
sudo pacman -Syu git

# disinstallazione (esempio Debian/Ubuntu)
sudo apt remove git
La versione della distro può essere più vecchia della 2.56.0. Controlla sempre con git --version: alcune funzioni recenti potrebbero non esserci.

    Risolvere un conflitto

    1. git status elenca i file in conflitto.
    2. Apri ogni file, scegli o combina le modifiche e rimuovi i marcatori <<<<<<<, =======, >>>>>>>.
    3. git add file per segnare il conflitto come risolto.
    4. Per un merge: git commit. Per un rebase: git rebase --continue.
    Rebase: riscrive la storia. Usalo sui branch locali o non ancora condivisi; su un branch già pubblicato preferisci merge.

    Annullare e recuperare

    # annulla le modifiche non salvate di un file
git restore file.txt

# annulla tutte le modifiche non salvate
git restore .

# togli un file dallo staging, senza perdere le modifiche
git restore --staged file.txt

# riporta un file alla versione di un commit precedente
git restore --source=HEAD~1 file.txt

# annulla l'ultimo commit mantenendo le modifiche in staging
git reset --soft HEAD~1

# annulla l'ultimo commit mantenendo le modifiche nel working tree
git reset HEAD~1

# annulla l'ultimo commit e butta via le modifiche (pericoloso)
git reset --hard HEAD~1

# riporta il branch alla versione remota (pericoloso)
git reset --hard origin/main

# annulla un commit già pubblicato con un nuovo commit
git revert <commit>

# anteprima dei file non tracciati che verrebbero eliminati
git clean -n

# elimina file e cartelle non tracciati
git clean -fd

# elimina anche i file ignorati
git clean -fdx
    Comandi distruttivi: reset --hard e clean -fdx cancellano modifiche non recuperabili con un semplice undo. Controlla sempre con git status e git clean -n prima di eseguirli.

git reset --hard HEAD@{1}

    Se qualcosa va storto

    SituazioneCosa fare
    Push rifiutatogit pull --rebase, risolvi i conflitti, poi git push.
    Commit sbagliato ma non pubblicatogit commit --amend oppure git reset --soft HEAD~1.
    Commit sbagliato già pubblicatogit revert <commit>: non riscrive la storia.
    Branch cancellato per erroregit reflog, trova il commit e ricrea il branch con git switch -c nome <commit>.
    HEAD staccata (detached)Crea un branch con git switch -c nuovo-branch oppure torna a git switch main.
    File ignorato per sbagliogit check-ignore -v file per capire quale regola lo esclude.
