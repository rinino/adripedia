Comandi slash

I comandi che iniziano con / trasformano una scorciatoia in un prompt. Alcuni sono inclusi, altri li definisci tu.

Come si usano

Scrivi / nel prompt: appare la lista. Continua a scrivere per filtrare, poi premi Enter sul comando scelto. 

/models

Comandi inclusi o disponibili

ComandoCosa fa
/newNuova sessione.
/sessionsElenca e riapre le sessioni.
/modelsScegli il modello.
/agentsScegli l'agente (Build, Plan, …).
/undoAnnulla l'ultimo messaggio utente e il lavoro successivo.
/redoRipristina il lavoro annullato.
/editorModifica il prompt nell'editor esterno.
/btw <domanda>Domanda laterale: usa il contesto ma non entra nella conversazione.
/highlightsRivedi le novità dell'ultima release.
/reloadRicarica la configurazione.
/mcpsGestisci i server MCP e l'autenticazione OAuth.
Suggerimento: la lista vera è quella che vedi digitando / nella tua installazione. Per tutte le azioni, anche quelle senza comando slash, usa Ctrl+P (command palette).

Creare un comando

Crea un file Markdown in una di queste cartelle:

~/.config/opencode/commands/review.md
.opencode/commands/review.md

Su Windows la prima è %USERPROFILE%\.config\opencode\commands\. Vengono scoperti solo i file .md. I percorsi annidati diventano parte del nome: team/review.md si invoca come /team/review.

Esempio minimo

Revisiona $ARGUMENTS per bug e test mancanti.

/review src/auth.ts invia: Revisiona src/auth.ts per bug e test mancanti.

Con frontmatter

---
description: Revisiona il codice
agent: plan
model: anthropic/claude-sonnet-5-5#high
---

Revisiona $ARGUMENTS. Riporta prima i bug.

In JSON

{
  "$schema": "https://opencode.ai/config.json",
  "commands": {
    "review": {
      "description": "Revisiona il codice",
      "template": "Revisiona $ARGUMENTS. Riporta prima i bug."
    }
  }
}

Campi

CampoComportamento
templateSolo JSON: il testo del prompt. In Markdown è il corpo del file.
descriptionTesto mostrato nelle liste e nella scoperta.
agentAgente selezionato quando il comando parte.
modelModello, con variante opzionale.
subagenttrue esegue in una sessione figlia in background; false forza la sessione corrente.
subtaskAlias deprecato di subagent.

Argomenti

$ARGUMENTS contiene tutta la stringa inserita:

Crea un componente React tipizzato chiamato $ARGUMENTS.

Con /component Account Settings, il segnaposto diventa Account Settings.

$1, $2, ecc. estraggono argomenti posizionali; le virgolette raggruppano le parole e vengono rimosse: 

Controlla $1. Concentrati su $2.

Con /check src/auth.ts "gestione errori", $1 diventa src/auth.ts e $2 diventa gestione errori. Il segnaposto con il numero più alto consuma anche tutto ciò che segue.

Se il template non contiene né $ARGUMENTS né segnaposto posizionali, gli argomenti non vuoti vengono aggiunti dopo una riga vuota.

Blocchi shell

Racchiudi un comando tra ! e i backtick per inserire il suo output prima dell'invio: 

Revisiona questo diff:

!`git diff --stat && git diff`
I blocchi shell vengono eseguiti quando OpenCode valuta il comando, fuori dal flusso dei permessi degli strumenti. Usali solo con sorgenti fidate e non inserire argomenti non fidati dentro i blocchi.

Esecuzione in background

---
description: Revisiona le modifiche
agent: general
subagent: true
---

Revisiona $ARGUMENTS per bug e test mancanti.

Il padre resta disponibile e conserva agente e modello. Quando il figlio finisce, OpenCode riporta il risultato o l'errore al padre.

Precedenza

Comandi Markdown e JSON condividono un unico registro. Le fonti successive sostituiscono i comandi con lo stesso nome: il progetto vince sul globale, e la cartella più vicina vince su quella antenata. Un comando personalizzato può anche sostituire un comando incluso.

Le modifiche ai file dei comandi vengono ricaricate automaticamente: salvi il file e /review è già aggiornato.
