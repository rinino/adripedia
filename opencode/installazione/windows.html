Installazione su Windows

Come verificare la versione, installare e aggiornare OpenCode V2 su Windows, gestire il servizio in background e sapere dove finiscono configurazione e dati.

Windows: i comandi di questa pagina si intendono eseguiti in PowerShell. La guida per Linux è in preparazione: Installazione su Linux.

Verificare la versione

Prima di tutto, controlla cosa stai usando:

opencode --version

I contenuti di questa sezione sono allineati alla V2 e verificati sulla versione 2.2.5 per Windows.

Installare

Il metodo più diretto è npm:

npm install --global @opencode/cli

Su Windows funziona anche winget. I metodi riconosciuti da opencode upgrade sono: curl, npm, pnpm, bun, yarn, vp, brew e winget.

Se opencode non viene riconosciuto dopo l'installazione, chiudi e riapri PowerShell: il percorso globale di npm entra nel PATH solo all'avvio di una nuova sessione.

Aggiornare

# ultima versione disponibile
opencode upgrade

# una versione specifica
opencode upgrade 2.0.21

# scegliendo il metodo di installazione
opencode upgrade 2.0.21 --method npm

update è un alias di upgrade.

Avviare la TUI

# nella cartella corrente
opencode

# in un'altra cartella
opencode C:\percorso\del\progetto

Senza argomenti, OpenCode apre la TUI nella directory in cui lanci il comando.

Il servizio in background

OpenCode usa un'architettura client/server: la TUI si collega a un servizio in background che possiede sessioni, configurazione, plugin e permessi. Normalmente viene avviato in automatico. 

opencode service status
opencode service restart
opencode service stop
opencode service start
Quando riavviare il servizio? Solo se è bloccato o non risponde. Le modifiche alla configurazione vengono ricaricate da sole: non serve riavviare nulla dopo aver salvato un file.

Per avviare la TUI con un server privato, isolato da quello condiviso: 

opencode --standalone

Per collegarti a un server specifico:

opencode --server http://localhost:4096

Se preferisci non usare affatto il servizio condiviso, puoi disattivarlo. Da quel momento i comandi useranno server privati, finché non lo riattivi. 

opencode service set disabled true
opencode service unset disabled

Dove sono i file

Per stampare tutti i percorsi globali su questa macchina:

opencode debug paths

Per stamparne uno solo:

opencode debug paths db
opencode debug paths config
opencode debug paths log
opencode debug paths data

I selettori disponibili sono: db, home, data, config, cache, state, tmp, bin, log, repos.

Su Windows la configurazione globale sta in %USERPROFILE%\.config\opencode\. Per i log, usa opencode debug paths log: il percorso dipende da come hai installato OpenCode.

Completamenti per PowerShell

Genera lo script di completamento:

opencode --completions powershell

Sono supportate anche bash, zsh, fish, sh e pwsh.

Disinstallare

# anteprima di cosa verrebbe rimosso
opencode uninstall --dry-run

# disinstalla davvero
opencode uninstall

La disinstallazione rimuove l'eseguibile e la cache globale, ma non tocca sessioni, configurazione e stato.

Problemi?

Se qualcosa non funziona, la sequenza di controllo è:

  1. opencode service status — il servizio è attivo?
  2. opencode api get /api/info — l'API risponde?
  3. opencode --standalone — il problema è del servizio condiviso o del progetto?
  4. opencode debug paths log — dove sono i log?
